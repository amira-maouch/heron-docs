# Welcome

Docs for building consumer apps on Heron: what's in an app, how to build
common things, best practices once you're past the basics, and how to move
between framework versions.

- **[App Structure](/docs/heron/app-structure)** — every file and folder in a
  Heron app, and what it's for.
- **[How-To Guides](/docs/guides/running-locally)** — task-focused
  walkthroughs: add a widget, add a route, wire up auth, use SSR, and more.
- **[Best Practices](/docs/best-practices/ssr)** — patterns worth following
  for SEO, SSR, and widget APIs once the basics click.
- **[Migration Guides](/docs/migration/1.13-to-2.0)** — step-by-step guides
  for moving between Heron versions, starting with `main` → the SSR branch.

## Adding a page

Every page here is a Markdown/MDX file under `docs/`. Folder structure maps
directly to the URL and sidebar, including nesting — so a new subfolder with
its own `_category_.json` becomes a new nested route automatically. Add a
file, commit, push — the deploy picks it up.

## Versioning

This site isn't versioned yet — there's a single, always-current set of docs.
When Heron cuts its next major version and old docs need to stay available,
run:

```bash
npm run docusaurus docs:version 1.0
```

That snapshots the current `docs/` into `versioned_docs/version-1.0/` and adds
a version switcher to the navbar. Keep editing `docs/` as the "next"
(unreleased) version after that.
