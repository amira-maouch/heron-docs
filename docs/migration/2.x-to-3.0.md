# Migrate a consumer app from Egret to Heron

Heron 3.0 renames the frontend framework from Egret to Heron. The Egret
backend, the `egret-ui` registry, and the `egretClient` service keep their
existing names.

Commit or stash the consumer app before starting.

## 1. Upgrade Heron

For a typical web consumer:

```bash
pnpm add \
  @heron-ws/app-runtime@^3.0.0 \
  @heron-ws/component-api@^6.0.0
```

If they are direct dependencies of your app, use these release versions:

- `@heron-ws/i18n@^2.0.0`
- `@heron-ws/page-engine@^2.0.0`
- `@heron-ws/app-runtime-core@^2.0.0`
- `@heron-ws/app-runtime-server@^2.0.0`
- `@heron-ws/app-runtime-native@^4.0.0`
- `@heron-ws/component-registry@^1.0.0`
- `@heron-ws/page-engine-components@^2.0.0`
- `@heron-ws/utils@^1.0.0`

## 2. Run the migrator

Apply the changes from the consumer app root:

```bash
pnpm exec heron-migrate-egret . --write
```

This updates framework names such as `egret:core:*` → `heron:core:*`,
`$egret` → `$heron`, and `egret-build-app` → `heron-build-app`.

Generated artifacts and lockfiles are skipped and will be recreated during the
build.

## 3. Check environment variables

Rename only the frontend framework settings:

| Before                       | After                        |
| ---------------------------- | ---------------------------- |
| `EGRET_WIDGETS_API_BASE_URL` | `HERON_WIDGETS_API_BASE_URL` |
| `EGRET_ENABLE_SCRIPT_CACHE`  | `HERON_ENABLE_SCRIPT_CACHE`  |
| `EGRET_CONFIG`               | `HERON_CONFIG`               |
| `EGRET_UNAUTHORIZED_PATH`    | `HERON_UNAUTHORIZED_PATH`    |
| `EGRET_BUILD_VERSION`        | `HERON_BUILD_VERSION`        |
| `EGRET_CODEGEN_FORCE`        | `HERON_CODEGEN_FORCE`        |

Keep Egret backend settings unchanged, including `EGRET_API_BASE_URL`,
`EGRET_AUTH_BASE_URL`, `EGRET_CRUD_BASE_URL`, and `EGRET_REALTIME_URL`.

Backend configuration is now read through the Heron runtime, for example:

```ts
$heron.getEnv("EGRET_API_BASE_URL");
```

## 4. Use the migrated registry branch

Use the `egret-to-heron-registry` branch of `heron_registry`:

```bash
cd ../heron_registry
git fetch origin
git switch egret-to-heron-registry
git pull --ff-only origin egret-to-heron-registry

pnpm install
pnpm --filter component-registry build:force
pnpm --filter component-registry start
```

Registry IDs such as `egret-ui` remain unchanged; only their framework-facing
bundle code was migrated.

## 5. Rebuild the consumer

With the migrated registry running, return to the consumer app and rebuild:

```bash
pnpm build:app
pnpm build
```

## Verify

```bash
pnpm exec heron-migrate-egret . --check
```

Confirm that metadata uses `heron:core:*`, scripts use `$heron`, and the browser
console has no `__EGRET_SHARED__` or unknown `core/*` component errors.
