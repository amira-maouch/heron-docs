# Migrating to the hydration stability update

This Heron update prevents SSR pages from disappearing after hydration,
removes guessed client-placeholder heights, and primes embedded translations
before the client tree mounts. SSR and CSR routes can still coexist, and
client-only bundles still load at runtime.

## What changes automatically

After upgrading the related `@heron-ws/*` packages together:

- hydrated SSR content is never replaced by a root loading fallback;
- embedded SSR translations are reused during hydration;
- parent widget scripts still wait for real child instances;
- CSR and mobile widgets still wait for their declared bundles and
  translations before their first visible mount; and
- a client-only boundary with unknown dimensions uses one atomic page reveal
  instead of showing a partial page that later collapses.

Existing apps remain valid. The steps below improve immediate SSR and layout
stability; they are not a requirement to keep the app running.

### 1. Install `2.3.0

`

```bash
pnpm add @heron-ws/app-runtime@^2.3.0

```

## 2. Add presentation contracts to browser-only components

Add `presentation` to each browser-only registry component's `contract.json`.

For a provider or portal that adds no document-flow UI:

```json
{
  "environment": ["browser"],
  "presentation": { "layout": "none" }
}
```

For a visual component with a predictable reusable footprint:

```json
{
  "environment": ["browser"],
  "presentation": {
    "layout": "reserved",
    "placeholder": {
      "width": "100%",
      "minHeight": 320,
      "className": "rounded-xl bg-muted"
    }
  }
}
```

`layout: "reserved"` requires a placeholder. Bump the component version,
rebuild/publish the registry contract, then rebuild consuming apps so their
vendored contract and `.bundle-lock.json` are refreshed.

## 3. Add widget placeholders only when needed

Do **not** add a placeholder to every widget. Add one when a widget needs
stable initial loading UI. On SSR this is normally the nearest
`renderMode: "client-only"` widget; on CSR web and mobile it may be any widget
whose resource-loading interval should show an authored box or skeleton:

```json
{
  "component": "egret:core:widget",
  "id": "client-chart",
  "renderMode": "client-only",
  "placeholder": {
    "width": "100%",
    "minHeight": 320,
    "className": "rounded-xl bg-muted"
  }
}
```

`presentation` is not a metadata key. Component defaults live under
`presentation` in registry `contract.json`; widget and layout overrides use
the top-level `placeholder` key in `metadata.json`. Ordinary component nodes
do not accept a per-instance metadata placeholder.

Use these rules:

- nonvisual component → `presentation.layout: "none"`, no widget placeholder;
- reusable visual size → component-level `layout: "reserved"` placeholder;
- instance-specific visual size or skeleton → widget metadata `placeholder`;
- unknown layout with no placeholder → no migration blocker; Heron uses atomic
  reveal for that SSR route.

Only the nearest client-only ancestor needs a widget placeholder for SSR. Its
subtree is one opaque client boundary. On CSR and mobile, an authored
placeholder remains visible until that widget's bundles, declared
translations, and platform styles are ready.

On CSR routes, loading boundaries apply independently to every widget in the
resolved tree. Audit persistent shell widgets such as sidebars, headers,
navigation, and toolbars—not only the destination page widget. Give each shell
widget an authored placeholder when its temporary absence would collapse or
rearrange the layout. A page-level placeholder does not cover sibling widgets
provided by the layout.

## 4. Check translations and first-paint scripts

No new translation API is required. Keep every first-paint namespace declared
through Heron's translation configuration so SSR, CSR, and mobile resource
gates can load it before mount. Missing or undeclared keys cannot be preloaded.

Avoid widget scripts that create first-paint text or layout after mount. Put
that state in metadata, props, translation resources, or loaders so the first
visible tree is already final.

## Verification checklist

- Reload an SSR route with network throttling: it never goes
  visible → empty → visible.
- Nonvisual client-only providers do not reserve blank space.
- Visual client-only regions keep the same footprint while loading.
- No raw translation keys appear before translated text.
- CSR routes still fetch runtime bundles normally.
- Hard-reloading a CSR route keeps persistent shell regions in place while
  their resources load.
- Authored widget placeholders appear while CSR/mobile resources load and are
  replaced once by the ready subtree.
- Parent widget scripts still start only after their real children mount.

For the complete presentation options, see
[CSR Placeholders in SSR Routes](/docs/guides/ssr/csr-placeholders).
